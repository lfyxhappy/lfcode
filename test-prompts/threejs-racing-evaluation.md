# Three.js 3D 赛车综合能力评测

## 用途

将以下内容直接发送给被评估模型，用于在约 30 分钟内完成一个可运行的 3D 赛车小游戏。

## 测试提示词

```text
请在 30 分钟内开发一个可运行的 3D 赛车小游戏，用于评估你的综合开发能力。

【技术约束】

1. 必须使用 Three.js 实现 3D 场景和游戏渲染。
2. 最终交付一个无需构建的 index.html，可通过浏览器和简单静态服务器运行。
3. 可以使用 Three.js CDN，但不得依赖 React、Vite、后端服务或其他构建流程。
4. 不使用本地图片、3D 模型、字体或音频素材；车辆、赛道、环境、障碍物和特效都使用程序化几何或 Canvas 生成。
5. 不要复制完整现成的赛车项目。
6. 不要等待进一步需求确认，请自行做出合理取舍。
7. 优先保证核心玩法完整，再补充视觉效果和高级功能。

【必须实现】

1. 一个第三人称追尾视角的 3D 赛车场景。
2. 一辆玩家车辆，支持 WASD 和方向键控制：
   - 前进、刹车或倒车
   - 左右转向
   - 基本加速、减速和转向惯性
3. 一个闭环赛道，至少包含：
   - 起点
   - 至少 2 个检查点
   - 终点
   - 赛道边界或碰撞区域
4. 单圈计时系统：
   - 当前时间
   - 最佳时间或历史最佳时间
   - 检查点进度
   - 完成一圈后的结果提示
5. 摄像机跟随：
   - 平滑追踪车辆
   - 根据车辆速度产生距离或视角变化
   - 车辆不会轻易跑出画面
6. 游戏状态：
   - 开始或重新开始
   - 计时中
   - 撞击或出界后的反馈
   - 完成一圈
7. 页面 UI：
   - 速度
   - 当前圈速
   - 检查点进度
   - 操作提示
   - 重置按钮
8. 至少一种明显的反馈效果：
   - 碰撞闪烁
   - 尘土或粒子
   - 速度线
   - 轮胎痕迹
   - 车辆倾斜
   - 计时完成动画
9. 页面必须有清晰的视觉层次，不能只是默认颜色的几何体堆叠。

【工程要求】

1. 代码结构清晰，避免把所有逻辑塞进一个难以维护的函数。
2. 将场景初始化、车辆控制、碰撞判断、摄像机跟随、计时状态和 UI 更新分开组织。
3. 对窗口尺寸变化进行响应式处理。
4. 不应出现未捕获的 JavaScript 异常。
5. 处理车辆出界、重复通过检查点、重复完成计时等边界情况。
6. 页面加载后应能立即开始游戏，不依赖额外配置。

【执行方式】

开始前只用几句话说明你的实现计划和优先级，然后立即编码。

如果时间不足，必须优先保证：

1. 游戏能够加载并显示 3D 场景；
2. 车辆可以驾驶；
3. 赛道、检查点和计时闭环可用；
4. 页面有基本 UI；
5. 最后再补充粒子、音效或高级视觉效果。

完成后请：

1. 说明如何运行；
2. 列出已实现功能；
3. 列出明确未实现或简化的部分；
4. 说明你做过的自测；
5. 如果有浏览器或自动化工具，请实际打开页面并检查控制台错误、页面是否可见以及核心交互是否正常。

不要伪造测试结果。
```

## 评测评分

总分 100 分：

- 可运行性与稳定性：20 分
  - 页面能启动、场景非空白、无致命错误、窗口缩放正常。
- 核心赛车玩法：25 分
  - 车辆控制、赛道、检查点、终点、计时和重置形成完整闭环。
- 3D 场景与视觉表现：15 分
  - 场景层次、灯光、材质、赛道辨识度和整体完成度。
- 交互与摄像机：15 分
  - 操控响应、惯性、摄像机跟随、速度反馈和碰撞反馈。
- 工程质量：15 分
  - 代码组织、状态管理、边界处理、响应式和错误控制。
- 细节与表现力：5 分
  - 粒子、尘土、车辆倾斜、速度线、动画或其他增强效果。
- 交付与自测：5 分
  - 运行说明、功能清单、限制说明和真实自测证据。

## 可选加分项

以下内容不计入基础 100 分，可用于同分区分：

- 简单 AI 对手；
- 漂移或抓地力差异；
- 多圈模式；
- 赛道小地图；
- 日夜或天气变化；
- 程序化音效；
- 触屏或移动端控制；
- 低帧率下的性能优化；
- 失败后可恢复且不刷新页面。
