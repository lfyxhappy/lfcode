# 设置页宽屏留白且重要快捷键缺少优先展示

## 优先级

中。问题不阻断设置操作，但模型页和快捷键页在桌面宽屏下浪费了接近一半的内容区域；快捷键页还将大量浏览器和低频命令排在前面，用户难以快速发现最需要记住的快捷键。

## 状态

已解决

## 问题

桌面端“设置 -> 快捷键”和“设置 -> 模型”页面在宽窗口中都只使用左侧约 720px 的固定内容宽度，右侧留下大块空白。两个页面仍保持单列长卡片，既没有利用可用横向空间，也增加了纵向滚动距离。

模型页中的默认模型配置、供应商和模型列表同样被限制在窄栏内。随着供应商和模型数量增加，页面会继续向下拉长，但右侧可用空间始终闲置。

页面顶部从“通用”分组开始展示全部命令，组内按标题排序。重要、常用快捷键与低频命令、未设置命令混排，用户打开页面后不能优先看到需要记忆和使用的核心快捷键。当前截图中“通用”分组首先出现大量浏览器相关命令，就是这一排序和分组策略的直接表现。

## 原因

### 已确认

- 快捷键页的粘性标题/搜索区与列表区分别写死了 `max-w-[720px]`，父容器没有居中或宽屏布局策略，因此窗口剩余宽度全部成为右侧空白：`packages/app/src/components/settings-keybinds.tsx:375`、`:409`。
- 模型页使用了完全相同的固定宽度：粘性标题/操作/搜索区和模型列表区分别设置 `max-w-[720px]`，因此截图中的右侧留白与快捷键页是同一布局根因：`packages/app/src/components/settings-models.tsx:289`、`:327`。
- `KeybindMeta` 只包含 `title` 和 `group`，没有“重要”“常用”“排序权重”等字段：`packages/app/src/components/settings-keybinds.tsx:21-24`。
- `groupedFor()` 在每个分组内只按本地化标题执行 `localeCompare`，不会优先展示核心命令、已设置命令或高频命令：`packages/app/src/components/settings-keybinds.tsx:143-157`。
- `groupFor()` 没有识别 `browser.*` 命令，未命中的命令统一回落到 `General`，因此浏览器打开、关闭、地址栏、前进后退等命令占据“通用”分组前部：`packages/app/src/components/settings-keybinds.tsx:48-64`。
- 通用命令模型 `CommandOption` / `CommandCatalogItem` 也没有快捷键页展示优先级字段，现有 `category` 仅提供命令分类文本：`packages/app/src/context/command.tsx:75-96`。

### 高概率原因

- 两个页面沿用了设置页的窄栏 `720px` 版式，但模型和快捷键都属于高密度、可利用横向空间的数据，没有针对宽屏桌面重新设计。
- 当前分组是根据命令 ID 前缀在页面内推断的，命令新增后如果未同步扩展 `groupFor()`，就会持续落入“通用”，进一步稀释核心快捷键。

### 待验证

- 需要确定“重要快捷键”的产品清单。建议至少覆盖命令面板、打开设置/项目、新建或切换会话、发送与中断、模型/Agent 切换、终端和浏览器开关等核心流程，但最终清单应由产品侧确认。
- 需要在常见桌面宽度（1280、1440、1920、2560）与较窄窗口下比较双列、自适应满宽和居中单列三种方案，分别确认模型选择器、模型卡片和快捷键编辑交互不会退化。

## 推荐解决方案

1. 去掉模型页和快捷键页标题区、搜索区及列表区硬编码的 `max-w-[720px]`，抽出一致的响应式设置内容容器。宽屏优先使用可控的满宽布局、网格分组或更高的自适应上限，窄屏保持单列。
2. 模型页可将默认模型配置保持整行，将供应商/模型卡片改为响应式网格；下拉选择器仍需保留足够的标签宽度和稳定的对齐关系。
3. 在快捷键列表顶部增加独立的“常用快捷键”分组，使用稳定的命令 ID 清单或显式元数据决定内容，避免依赖中文标题排序。常用分组只做快捷入口，原分类中仍保留对应命令，或通过明确的去重规则避免用户误解。
4. 为快捷键展示元数据增加可维护的分组与优先级来源，例如 `shortcutGroup`、`shortcutPriority` 或页面侧集中配置；组内按“核心优先级 -> 是否已设置 -> 本地化标题”排序。
5. 将 `browser.*` 明确归入“浏览器”分组，或至少从“通用”迁出；不要继续让未知前缀静默污染“通用”。如果新增分组，需要同步所有本地化文案。
6. 保持搜索结果按匹配度排序；用户输入搜索词时不应被常用优先级覆盖。模型搜索、模型选择、快捷键录制、冲突提示和重置默认值的现有行为也应保持不变。
